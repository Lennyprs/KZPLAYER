COMPORTEMENT GITHUB
- Un lot annule ne peut plus etre pris en charge ni valide comme APK disponible.
- Le script actualise le statut pendant Gradle (environ toutes les vingt secondes, hors attente de reponse Google). S'il constate une annulation, il arrete le groupe de processus de ce lot, pas les compilations des autres marques.
- Le statut est aussi controle avant publication et a la confirmation finale cote Google.
- Si une annulation intervient pendant un envoi deja commence, le script tente de supprimer UNIQUEMENT le nouveau fichier du lot annule. Le fichier de l'APK precedente n'est pas supprime.
- En cas d'incertitude reseau, le script n'annonce pas aveuglement un echec et ne supprime pas une APK potentiellement deja validee.
- Une execution GitHub deja demarree avec l'ancien script ne peut pas recevoir le nouveau code en direct. Elle peut continuer son etape, mais le backend V100 refuse la validation tardive d'un lot annule. L'arret cooperatif s'applique aux executions utilisant le nouveau script.
- Le bouton n'annule pas globalement un workflow partage par plusieurs marques et ne change aucune cle de signature.
- Les mises a jour de code ne ressuscitent pas automatiquement la derniere demande annulee. Une nouvelle compilation demande une action explicite du revendeur.
