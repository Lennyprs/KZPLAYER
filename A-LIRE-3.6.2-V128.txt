CORRECTION VIDEO CIBLEE
- Pour les VOD 4K/Dolby Vision non protegees : le classement est applique
  APRES le classement de capacites Media3, pas seulement dans le selecteur
  MIME. Sinon Media3 peut remettre le logiciel devant le materiel.
- Materiel completement compatible en premier ; ensuite materiel qui
  annonce le support fonctionnel du profil mais sous-declare ses limites
  de performance/taille ; logiciel ensuite. Les codecs materiels sans
  support fonctionnel ne sont pas forces en premiere intention.
- Apres echec d'un decodeur logiciel Android, autoriser un essai materiel
  borne de la meme famille declaree par Android, meme si les capacites
  sont sous-declarees. Pour Dolby Vision, seulement avec une couche de
  base HEVC/AVC compatible reconnue par Media3, jamais une base inventee.
- Au maximum deux reprises par lecture ; exclusion du codec en echec,
  reprise de position et renouvellement du lien MAC/Stalker conserves.
- Le correctif de profil HEVC Main10 / AVC High de V126 est conserve.
- Full HD ordinaire, direct, replay, DRM, audio, sous-titres, buffers,
  surfaces et gestion reseau restent sur leurs chemins existants.
- Les renderers d'extension Media3 sont conserves ; pas de suppression
  de l'audio FFmpeg et pas de fausse promesse de video FFmpeg 4K.
- La fenetre d'erreur montre aussi les codecs proposes, materiel/logiciel,
  sans URL, MAC, commande ni jeton. Elle ne declare plus le boitier
  incompatible sur la seule base du codec logiciel en echec.

FENETRE ET RAPPORT DE PLANTAGE
- Les erreurs VOD passent par une fenetre appartenant au lecteur, fermee
  a l'arret/destruction. La fermeture protege le cas IllegalArgumentException
  lorsque la vue a deja ete retiree ; affichage refuse pour une activite
  detruite, jeton de fenetre expire gere, anciens callbacks joueur ignores.
- Retrait des dismiss explicites redondants dans les menus de choix qui
  se ferment deja automatiquement. Le watchdog de demarrage est arrete
  quand l'erreur finale est affichee pour ne pas relancer derriere la fenetre.
- Le texte « KZ Player 3.4.0 » etait CODE EN DUR dans CrashDiagnostics :
  ce n'etait pas une preuve que l'ancienne version etait installee.
  Les NOUVEAUX rapports affichent maintenant BuildConfig.VERSION_NAME.
  Un ancien rapport deja enregistre conserve logiquement son ancien texte.

LIMITES HONNETES
Prioriser le bon codec et exploiter une couche compatible ne convertit
pas un fichier. Une piste alternative doit exister pour reduire la qualite.
Aucun transcodage serveur, conversion generale Dolby Vision -> SDR ni
ajout de puissance materielle n'est effectue. Les seules photos ne prouvent
pas la cause historique de la regression ou le resultat du nouveau correctif.

INSTALLATION
1) Extraire le projet a la racine du depot, y compris .github s'il est cache.
   Remplacer les fichiers correspondants sans supprimer le reste ni les
   secrets de signature. Si un autre chantier a modifie ce depot depuis
   V127, fusionner au lieu d'ecraser ces modifications independantes.
2) Dans le terminal du depot :

git add app/build.gradle app/src A-LIRE-3.6.2-V128.txt
git commit -m "Priorise le decodage materiel et securise les erreurs lecteur - 3.6.2"
git push

3) Attendre la NOUVELLE execution GitHub verte sur ce commit. Recuperer
   son app-release-signed.apk et installer en mise a jour, sans desinstaller.
4) Reessayer le meme film. Le diagnostic indique le codec effectivement
   initialise et les candidats proposes, sans exposer les identifiants IPTV.
