--------------------------

lecteur, source/extracteurs Media3, fabrique native, file synchrone, buffers,
paramètres audio/vidéo, préparation/lecture, sélection des transports et

démarrage VOD de cette référence sont donc rétablies, pas uniquement ses

1080p artificielle.

de l'archive V117 ; leurs ajouts récents d'historique/propriétaire restent.

-----------------------------------------------------

  récents live/propriétaires et sécurité de fermeture des menus conservés ;

Aucun de ces points n'est présenté comme une preuve de la cause de la panne.

par l'ancien assemblage V141.

INSTALLATION
------------
1. Extraire ce ZIP COMPLET dans la racine du dépôt KZPLAYER contenant app,
   tools, .github et build.gradle. Remplacer les fichiers.
2. Dans cette racine, exécuter :

   python3 tools/release/remove_libvlc_v135.py

   Le nom historique du script est conservé. Il est actualisé pour 3.7.6 et
   retire les anciens fichiers VLC/essais VOD. Il NE retire PAS la nouvelle
   activité replay ni le garde-fou de transport. Une extraction seule ne
   supprime pas les fichiers obsolètes du dépôt ; ne pas sauter cette étape.
3. Exactement ces trois commandes Git :

   git add -A app tools/release/remove_libvlc_v135.py A-LIRE-3.7.6-V142.txt REFERENCE-LECTURE-V117.json
   git commit -m "Reprend le lecteur complet V117 et preserve le replay - 3.7.6"
   git push

4. Attendre que le workflow Android officiel soit entièrement vert.
5. Installer le nouvel APK officiel en mise à jour SANS désinstaller et sans
   effacer les données. Vérifier la version 3.7.6 avant comparaison de lecture.
   Les APK personnalisés restent dans leur circuit et package propres.
6. Relancer le même contenu. En cas d'échec, le message doit afficher
   Lecteur : archive 3.5.3 V117 et KZ PLAYER : 3.7.6. Une photo complète de ce
   message permet de vérifier le chemin réellement installé, pas seulement
   le nom du ZIP envoyé sur GitHub. Cadrer sans notes privées autour de l'écran.
Les guides V112/V141 présents sont historiques ; suivre celui-ci.

VÉRIFICATIONS ET LIMITES
-----------------------
87 méthodes JVM locales, dont 18 tests du garde-fou de variantes (identifiant,
origine, port, jetons opaques, paramètres stream numériques, fragments et
fichiers locaux), 37 contrôles de recherche Java et 137 XML analysés.
Comparaison des blocs de code de lecture avec l'archive réelle : construction
HTTP/source/fabrique/buffers, audio/vidéo, démarrage/reconnexion, sous-titres et
préparation/lecture. Les blocs testés sont identiques à ceux de l'archive,
hormis la fermeture sûre du dialogue précédant une nouvelle lecture.
Code de replay actuel vérifié identique après renommage de classe.
Les fichiers API, recherche, catégories, historique, fiches et sécurité sont
vérifiés inchangés par rapport à 3.7.5.
Extraction simulée et nettoyage idempotent sur les anciennes versions.

Les tests locaux utilisant des interfaces Android minimales ne remplacent
PAS une compilation Android/Kotlin, un workflow GitHub réussi ni une lecture
native sur X96Q. Aucun APK signé, push ou installation réalisé ici. Cette
livraison est une restauration plus fidèle, PAS une preuve que la vidéo, le
son, le HDR et la fluidité fonctionnent maintenant. Si la panne persiste, il
faudra encore comparer l'archive de référence réellement installée et son
résultat actuel sur le même contenu ; sa réussite passée ne garantit pas
l'état actuel du flux ou du boîtier.
